## 1. Сессии Django вместо localStorage

- Проверить, что `SessionMiddleware` подключён (уже есть по умолчанию)
- Добавить `SESSION_ENGINE = 'django.contrib.sessions.backends.db'` (опционально)

### 1.2. Views (weather/views.py)
- `index`: читать сессию `request.session.get('last_city')`, если есть — передавать в контекст
- `weather_data`: после успешного ответа — сохранять город в сессию:
  ```python
  request.session['last_city'] = {'name': city, 'lat': lat, 'lon': lon}
  ```
- `index`: передавать `last_city` в шаблон

### 1.3. Шаблон (weather/templates/weather/base.html)
- Добавить скрытый input с данными последнего города из сессии:
  ```html
  {% if last_city %}
  <input type="hidden" id="last-city-data" value='{{ last_city|json_script:"last-city" }}'>
  {% endif %}
  ```
- Или проще: передать через data-атрибут body:
  ```html
  <body class="bg-day-clear" data-last-city='{{ last_city|default:"{}"|escapejs }}'>
  ```

### 1.4. JS (static/js/app.js)
- Убрать `localStorage.setItem/getItem`
- При инициализации читать данные из `data-last-city` атрибута body

### 1.5. Новый view (weather/views.py)
- `save_city`: POST `/api/save-city/` — принимает JSON `{name, lat, lon}`, сохраняет в `request.session`

## 2. Адаптивный фон через template tags

### 2.1. Template tag (weather/templatetags/weather_filters.py)
- Добавить фильтр `bg_class`:
  ```python
  @register.filter
  def bg_class(code, is_day):
      bg = wmo_bg(code)
      prefix = 'day' if is_day else 'night'
      return f'bg-{prefix}-{bg}'
  ```

### 2.2. Шаблон (weather/templates/weather/base.html)
- Установить класс фона на body при загрузке:
  ```html
  <body class="{{ current_weather_code|bg_class:current_is_day|default:'bg-day-clear' }}">
  ```
- Но WMO-код доступен только после AJAX-запроса, поэтому:
  - При первой загрузке (без данных) — дефолтный фон `bg-day-clear`
  - JS обновляет фон через `setBackground()` как раньше (это уже работает)

### 2.3. Альтернатива: начальная погода по умолчанию
- В `views.index` загружать погоду для города из сессии (или Москва по умолчанию)
- Передавать `current_code` и `is_day` в шаблон
- Устанавливать фон на body сразу при рендере

## 3. Docker-конфигурация

### 3.1. Dockerfile
```dockerfile
FROM python:3.11-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1

WORKDIR /app

COPY requirements.txt .
RUN pip install --upgrade pip && pip install -r requirements.txt

COPY . .

RUN python manage.py collectstatic --noinput

EXPOSE 8000

CMD ["gunicorn", "weather_project.wsgi:application", "--bind", "0.0.0.0:8000", "--workers", "3"]
```

### 3.2. docker-compose.yml
```yaml
version: '3.8'

services:
  web:
    build: .
    ports:
      - "8000:8000"
    volumes:
      - static_data:/app/staticfiles
    env_file:
      - .env
    depends_on:
      - db

  db:
    image: postgres:15-alpine
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      POSTGRES_DB: weather
      POSTGRES_USER: weather
      POSTGRES_PASSWORD: weather

volumes:
  postgres_data:
  static_data:
```

### 3.3. .env.example
```
SECRET_KEY=changeme
DEBUG=0
ALLOWED_HOSTS=localhost,127.0.0.1
DATABASE_URL=postgres://weather:weather@db:5432/weather
```

### 3.6. Nginx-конфиг (опционально, для продакшена)
Файл `nginx.conf`:
```nginx
upstream weather_app {
    server web:8000;
}

server {
    listen 80;
    server_name _;

    location /static/ {
        alias /app/staticfiles/;
        expires 30d;
    }

    location / {
        proxy_pass http://weather_app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
