# План: Перенос weather-app на Django

## Архитектура

**Backend**: Django (Python) — серверный рендеринг шаблонов + API-прокси для Open-Meteo.
**Frontend**: существующие `css/style.css` и `js/app.js` как static-файлы, минимальные правки для AJAX-запросов к Django.
**API**: Open-Meteo (бесплатный, без ключа) — геокодинг + прогноз погоды.

## Требования к реализации

### 1. Настройка проекта (settings.py, urls.py)
- `INSTALLED_APPS`: `'weather'`
- `STATIC_URL = '/static/'`, `STATICFILES_DIRS = [BASE_DIR / 'static']`
- `TEMPLATES` с путём `weather/templates/`
- CORS не нужен (same-origin)

### 2. Views (`weather/views.py`)
| View | URL | Описание |
|------|-----|----------|
| `index` | `/` | Рендерит `base.html` |
| `weather_data` | `/api/weather/` | GET `?lat=&lon=&city=` → fetch к Open-Meteo Forecast API → JSON response |
| `city_search` | `/api/search/` | GET `?name=` → fetch к Open-Meteo Geocoding API → JSON suggestions |

- Использовать `requests` для серверных вызовов к Open-Meteo
- Обернуть в `JsonResponse`
- Error handling: сетевые ошибки → 500 JSON

### 3. Шаблон (`weather/templates/weather/base.html`)
- Наследует HTML из `index.html`
- `{% load weather_filters %}`
- `<link rel="stylesheet" href="{% static 'css/style.css' %}">`
- `<script src="{% static 'js/app.js' %}"></script>`
- Кастомные фильтры для WMO-иконок и фоновых классов (перенести логику из JS в Python)

### 4. Template tags (`weather/templatetags/weather_filters.py`)
- `wmo_icon code is_day` → возвращает emoji (dayIcon / nightIcon)
- `wmo_bg code` → возвращает строку ('clear', 'clouds', ... )
- `wmo_desc code` → возвращает описание ('Ясно', 'Дождь', ...)

### 5. Обновление JS (`static/js/app.js`)
- `searchCity()` → `fetch('/api/search/?name=' + query)`
- `loadWeather()` → `fetch('/api/weather/?lat=' + lat + '&lon=' + lon + '&city=' + name)`
- Остальная логика (рендер DOM, autocomplete, debounce) — без изменений
- WMO-маппинг оставить в JS для мгновенной реакции autocomplete

### 6. requirements.txt
```
Django>=5.0
requests>=2.31
```

## Пошаговый план

1. **Создать Django-проект**: `django-admin startproject weather_project .`
2. **Создать приложение**: `python manage.py startapp weather`
3. **requirements.txt**: создать файл с Django + requests
4. **settings.py**: настроить INSTALLED_APPS, STATICFILES_DIRS, TEMPLATES
5. **weather/urls.py**: маршруты `/`, `/api/weather/`, `/api/search/`
6. **weather_project/urls.py**: include `weather.urls`
7. **weather/views.py**: 3 view-функции (index, weather_data, city_search)
8. **weather/templatetags/weather_filters.py**: фильтры для WMO-кодов
9. **weather/templates/weather/base.html**: HTML-шаблон
10. **static/js/app.js**: заменить fetch-URLы на Django endpoints
11. **Проверка**: `python manage.py runserver`

## Verification
- `python manage.py runserver` → страница открывается на `http://127.0.0.1:8000/`
- Поиск города → autocomplete работает (AJAX → `/api/search/`)
- Выбор города → погода загружается (AJAX → `/api/weather/`)
- Визуал идентичен оригиналу (те же градиенты, карточки, иконки)
